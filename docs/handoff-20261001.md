## 3. 新电脑从源码恢复（先网页版）

安装 Git、Node.js 22 LTS（至少 22.19）、uv。优先用本机操作系统的 Python/Node 运行；Windows 首次建议 PowerShell 原生环境，暂不引入 WSL 的音频、权限和端口额外变量。不需要为了网页版安装 Rust。

在准备存放项目的目录执行，以下通用命令可在 PowerShell 或 macOS/Linux shell 使用：

```sh
git clone --branch feat/pi-realtime-coach-agent-loop --single-branch https://github.com/luguochang/meeting-copilot.git
cd meeting-copilot
git branch --show-current
git log -3 --oneline
uv python install 3.13 3.11
uv sync --project code/web_mvp/backend --python 3.13 --frozen --group dev
npm --prefix code/web_mvp/frontend_v2 ci
npm --prefix code/web_mvp/frontend_v2 run build
npm --prefix code/agent_runtime/pi_coach_bridge ci
uv venv --python 3.11 code/asr_runtime/.venv-funasr
```

Windows PowerShell 安装语音依赖：

```powershell
uv pip install --python code/asr_runtime/.venv-funasr/Scripts/python.exe -r code/asr_runtime/requirements-funasr.lock
```

macOS/Linux 对应命令：

```sh
uv pip install --python code/asr_runtime/.venv-funasr/bin/python -r code/asr_runtime/requirements-funasr.lock
```

随后回到/保持仓库根目录：

```sh
uv run --project code/web_mvp/backend python tools/web_quality.py models
uv run --project code/web_mvp/backend python tools/web_quality.py doctor
uv run --project code/web_mvp/backend python tools/web_quality.py start
```

打开 <http://127.0.0.1:8765/workbench>。这是后端托管构建好的前端，日常不用另启 Vite。下载约 3.1GB 语音推理文件，建议预留至少 10GB 磁盘及 16GB 内存。公开下载链接、哈希与许可边界见 [部署手册第二节](web-deployment.md#2-本地模型的公开下载来源)。本地没有通用聊天大模型；五类模型用于识别、精修、VAD、标点和说话人区分。

日常命令：

```sh
uv run --project code/web_mvp/backend python tools/web_quality.py status
uv run --project code/web_mvp/backend python tools/web_quality.py stop
uv run --project code/web_mvp/backend python tools/web_quality.py start
```

Windows 自定义数据盘示例：

```powershell
uv run --project code/web_mvp/backend python tools/web_quality.py models --model-root D:/Talktrace/models
uv run --project code/web_mvp/backend python tools/web_quality.py start --port 8765 --model-root D:/Talktrace/models --data-dir D:/Talktrace/meetings
uv run --project code/web_mvp/backend python tools/web_quality.py status --port 8765 --data-dir D:/Talktrace/meetings
```

如果以前已经克隆，先确认分支与工作区状态，再 `git pull --ff-only origin feat/pi-realtime-coach-agent-loop`。若有本地修改或分叉，先保留并处理，不 reset、不强推。

### 平台问题的处理顺序

锁定依赖在旧 Mac 上可用，不代表每个版本均有 Windows/Linux wheel，尤其 torch/torchaudio 等二进制依赖。安装失败应记录 OS/CPU、Python 版本、失败包和完整错误，在目标平台修正兼容组合并补验证；不要为了启动成功跳过精修。不要直接复制 Mac 的 `.venv`、`node_modules`、Rust target 到 Windows。

Linux 若缺 PortAudio/libsndfile 等系统库，按具体错误补系统依赖；桌面构建另有平台工具链要求。当前文档不宣称这些平台已完成全新安装验证。模型哈希变化必须核对上游与清单，不得关闭校验绕过。

## 4. Provider、采集和质量设置

在 AI 设置分别确认通用、实时、校对模型，测试连接/工具调用，再保存。旧机使用 `https://codexai.club`、`gpt-6-sol`、Responses 协议；这是网关型号，不保证其他账号/Provider 提供同名模型。该型号快速配置将 `thinkingLevel=off` 映射为 `reasoning.effort=low`。Key 重新在本机填写，不在文档、提交或截图里粘贴。

必须区分三种检查：`doctor` 不访问付费 Provider；普通文本能返回不代表 tool calling 可用；工具探测通过也不代表会议内容有价值。最后必须测真实问题、持续讨论、跨题历史和会后产物。

- `/settings`：确认 `l2_correction_enabled`、`l3_normalize_enabled`、`suggestions.enabled`，并检查会议级建议策略。
- `/providers/asr/runtime`：本地精修不仅配置 prewarm，还要实际加载成功。空闲模型可卸载，需结合会议开始后的状态判断。
- 纯网页当前只采集麦克风；系统声音和双轨依赖 Tauri 原生桥。戴耳机时浏览器可能根本听不到对方，不能归咎于 Pi 没理解。
- 录音导入与实时麦克风走不同入口；导入成功不替代实时验收。
- 不用裸 uvicorn 或历史启动参数替代完整入口，否则可能回到只流式识别的 `online_only`。

## 5. 会议数据如何迁移

默认只通过 Git 迁移代码，先用新工作区验收。需要自己的旧会议时再单独迁移私有数据，禁止上传 GitHub。

旧机数据目录为 `artifacts/tmp/web_mvp_ui_review`，包含 `meeting_copilot.db`、其他兼容数据库、`audio_assets/`、`meeting_preparation/` 和私有设置。不能只复制一个数据库就认为录音也迁移了。

1. 在旧机结束会议，再用该实例的 `stop --port 8991 --data-dir artifacts/tmp/web_mvp_ui_review` 停止服务，确认不再有进程写入。不要热拷贝 SQLite 主文件而丢掉 WAL。
2. 对整个目录做私有离线备份，保留原件；将迁移副本传至本人新机。备份可能包含 Key、录音与会议文字，不向他人分发。
3. 在**迁移副本**中排除 `settings/provider.json`，新机重新配置 Provider；不要携带 `server.pid`、`server.pid.runtime-identity.json` 等旧进程标识。无需迁移运行日志。不要删除原数据目录里的文件。
4. 用新机的 `--data-dir` 指向迁移副本，先检查会议列表、转写修订、历史、文档和音频读取。若旧记录含旧机绝对路径，按实际缺失记录修复；跨 OS 历史音频迁移尚未实测，不能承诺直接复制就完整可用。
5. 五类模型可以单独复制以省下载，仍须执行 `doctor` 验证哈希；Python/Node 依赖必须在新平台重装。

本次只写交接与推送源码，没有停止旧机服务、迁移私人数据或替用户发出文件。

## 6. 核心代码导航与 Pi 的边界

| 要改什么 | 先看哪里 |
| --- | --- |
| 固定部署、模型与运行检查 | `tools/web_quality.py`、`tools/workbench_server.py`、`tests/test_web_quality.py` |
| 模型文件与语音推理 | `code/asr_runtime/model_packs/`、`code/asr_runtime/scripts/` |
| 流式识别、本地精修、远程文字校对 | `code/web_mvp/backend/meeting_copilot_web_mvp/` 下 `asr_stream.py`、`asr_refiner.py`、`realtime_transcript_correction.py` |
| 快答触发、任务调度、结果提交 | 同目录 `realtime_answer_copilot.py`、`realtime_intelligence.py`、`app.py` |
| Pi Python 桥与 Agent 工具 | 同目录 `pi_coach_runtime.py`；`code/agent_runtime/pi_coach_bridge/src/runtime.mjs` |
| 右侧阅读与调整 | `code/web_mvp/frontend_v2/src/features/live-meeting/` 下 `AnswerCoachReader.tsx`、`useCoachRequests.ts`、`PiSupplement.tsx` |
| 双栏、目标与事实 | 同目录 `MeetingSplitPane.tsx`、`MeetingFactsPanel.tsx`、`CoachSignals.tsx` |
| 桌面采集、系统声音与客户端构建 | `code/desktop_tauri/`，相关 `tools/*runtime*`、`tools/package_*` |

当前快答、校对、摘要、询问 AI 主要直接调用模型。Pi 处理深化与教练判断：`full` 有上下文/历史证据工具，`candidate_fast` 按候选限制工具，`deep_answer` 当前主要只有提交/静默工具，并未开放自主历史检索。最多 2 Agent turns / 4 tool calls，最多 8 个内存 Session，正式历史在 SQLite。当前使用 SDK，没有 fork Pi 源码。

因此，“用了 Pi”不意味着会自动更聪明、更快或具备联网搜索。后续有价值的增量是有界跨段取证、议题持续跟踪、用新证据关闭旧问题；不要把最近一分钟重写成摘要当作 Agent 优势。完整流程图和直接调用对比见 [架构说明](architecture-current-pi.md)。
