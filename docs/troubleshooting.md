# 故障排查

## 启动时出现黑色命令行窗口

`0.1.0` 最新 Windows 安装包已改为无控制台方式启动本地后台，并且不再通过 `.cmd` 文件中转。若仍看到黑框：

1. 核对安装包 SHA-256 是否为 `7d077e35f1e67da059a1291865d858f95eaa25c7257387b298b80187cc405463`。
2. 从“已安装的应用”卸载旧版，再安装 GitHub Release 中的最新文件。
3. 确认黑框的进程路径；开发环境中的 `npm.cmd`、终端或其他程序不属于客户端。

任务管理器中随客户端出现一个打包 `python.exe` 是正常的本地服务。它不应显示命令行窗口，也应在客户端退出后自动结束。

## 数据或能力包为什么在系统盘

安装目录只保存程序文件。会议数据库、录音、日志和能力包默认使用当前用户的 `%LOCALAPPDATA%`，以避免升级或卸载误删数据。要整体迁移到其他磁盘，请先完全退出客户端，再设置用户环境变量：

```powershell
setx MEETING_COPILOT_STORAGE_DIR "E:\TalktraceData"
```

重新启动后，新数据和导入的能力包会写入该目录。WebView2 运行缓存仍可能出现在系统盘的 `%LOCALAPPDATA%\com.meetingcopilot.desktop\EBWebView`，它不是模型目录。

## 工作台无法打开

先检查服务状态：

```powershell
cd code\web_mvp\backend
uv run python ..\..\..\tools\workbench_server.py status
```

如果前端来源校验失败，重新构建 `code/web_mvp/frontend_v2` 后再启动服务。若 `8765` 被占用，先停止旧进程，或在开发模式中为 Uvicorn 和 `VITE_DEV_API_TARGET` 使用同一个新端口。

## 页面有样式但接口报错

开发模式必须显式设置后端地址：

```powershell
$env:VITE_DEV_API_TARGET = "http://127.0.0.1:8765"
npm run dev
```

确认 `http://127.0.0.1:8765/health` 可访问，并检查浏览器控制台是否出现跨域、代理或网络错误。

## 麦克风不可用

1. 在 Windows 隐私设置中允许桌面应用访问麦克风。
2. 关闭正在独占设备的录音或会议软件。
3. 回到会议预检窗口重新选择输入设备。
4. 普通浏览器中确认站点的麦克风权限未被永久拒绝。

macOS/Chrome 还需要确认两件事：

1. Mac 已解锁且 Chrome 在前台。点击“检查麦克风”后，如果出现权限气泡，请选择“仅这次访问时允许”或“访问该网站时允许”。没有弹窗时，检查地址栏左侧的麦克风图标以及“系统设置 → 隐私与安全性 → 麦克风”。
2. 预检会把“等待麦克风权限”和“权限已通过，正在采样输入音量”分开显示，权限等待最多 8 秒；超时会回到可重试状态，不会继续占用迟到返回的音轨。

开发环境如果之前启动过多次隔离 Workbench，先停止旧实例再重试。多个遗留 FunASR resident worker 会互相占用唯一实时识别进程，日志通常表现为 `resident_busy` 或 `FunasrResidentUnavailableError`；不要直接按端口杀进程，应使用各实例自己的 `server.pid` 和运行身份记录精确停止。

系统音频和双轨采集依赖 Tauri 桌面端；普通浏览器不提供相同能力。

### 页面一直显示“检查麦克风”时先区分三种状态

1. **按钮可点、尚未检查**：还没有调用 `getUserMedia()`，与 Pi/DeepSeek 无关。
2. **等待麦克风权限 / 等待授权**：浏览器原生权限气泡正在等用户决定。网页自动化和后端日志
   都不能代替这次安全点击；在浏览器顶部选择“仅这次访问时允许”，或从地址栏左侧站点权限允许。
3. **已授权，正在采样**：权限已经通过，接下来才检查非零输入音量和 `AudioContext`。

当前实现对第 2 步最多等待 8 秒，随后恢复按钮并允许重试。若远程协作或人工响应来不及在 8 秒内
点击，先在地址栏站点权限中允许当前精确 origin（端口不同属于不同 origin），再点击“检查麦克风”。
不要反复重启 Pi SDK、FunASR 或后端来处理一个仍处于 `permission prompt` 的页面。

### Chrome 与 Codex 内置浏览器不是同一个权限上下文

Chrome 桌面窗口和 Codex 的内置浏览器使用不同的浏览器 profile/权限存储；即使它们打开相同
页面，也不能互相继承麦克风授权。`127.0.0.1:8981`、`127.0.0.1:8991` 等不同端口也属于不同
origin，必须在实际运行页面的那个 profile 中单独允许。麦克风授权气泡属于浏览器 chrome（系统
级 UI），不属于网页 DOM，因此页面截图、DOM 快照或后端日志都不会显示“仅这次访问时允许”这个
按钮；需要在对应浏览器窗口的原生提示或地址栏站点权限中完成操作。授权后再以同一窗口重试，
不要把 Codex 内置浏览器里看到的授权状态当成 Chrome 的授权状态。

还要先确认页面端口确实有服务：页面标题为“无法访问此站点”或 `/health` 不通时，先用对应
`server.pid` 的 managed launcher 恢复服务。旧页面指向一个已经关闭的端口时，它不可能完成麦克风
检查；这同样不是 Pi harness/loop 的问题。

## 没有实时转写

- 打开“离线能力”确认 ASR 运行时已就绪。
- 检查音频电平是否有输入。
- 确认能力包平台与当前系统匹配，且导入校验已完成。
- 查看诊断抽屉中的 ASR worker 和后台任务状态。

从源码使用 `tools/workbench_server.py` 启动时，若未配置 sealed runtime
manifest，启动器会检查本机 ModelScope 缓存中的完整 FunASR 文件转写模型
集（离线模型、VAD、标点）。三个目录都必须同时包含 `model.pt` 和
`config.yaml`；缺任一文件时会诚实降级，不会联网下载或从另一个显式缓存
目录静默回退。打包桌面运行时仍只使用能力包清单中的资源。

基础安装不包含完整离线模型时，需要先导入对应 `.mcpkg` 能力包。

## AI 建议或摘要不可用

1. 打开“设置”检查服务地址、模型和接口风格。
2. 重新输入 API Key 并执行连接检测。
3. 确认服务地址支持应用选择的 OpenAI-compatible 接口。
4. 检查账户额度、超时和网络代理。

AI 服务失败不会删除本地会议记录。恢复连接后可在复盘页面重试支持的分析任务。

## 导入录音失败

- 确认文件仍存在且当前用户有读取权限。
- 检查磁盘剩余空间。
- 使用常见音频格式，并避免损坏或只有容器头的文件。
- 不要从应用数据目录内部再次导入应用自己管理的音频。

## 生成诊断包

```powershell
code\web_mvp\backend\.venv\Scripts\python tools\generate_diagnostic_bundle.py
```

诊断文件写入已忽略的本地产物目录。对外发送前请检查其中是否包含不应分享的会议标题、文本或环境信息。
