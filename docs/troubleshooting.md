# 故障排查

## 启动时出现黑色命令行窗口

`0.1.0` 最新 Windows 安装包已改为无控制台方式启动本地后台，并且不再通过 `.cmd` 文件中转。若仍看到黑框：

1. 核对安装包 SHA-256 是否为 `a1f89e1252c031320701953c53b58a29ea29463ef905ee5e9074eb12db207dec`。
2. 从“已安装的应用”卸载旧版，再安装 GitHub Release 中的最新文件。
3. 确认黑框的进程路径；开发环境中的 `npm.cmd`、终端或其他程序不属于客户端。

任务管理器中随客户端出现一个打包 `python.exe` 是正常的本地服务。它不应显示命令行窗口，也应在客户端退出后自动结束。

## 数据或能力包为什么在系统盘

安装目录只保存程序文件。会议数据库、录音、日志和能力包默认使用当前用户的 `%LOCALAPPDATA%`，以避免升级或卸载误删数据。要整体迁移到其他磁盘，请先完全退出客户端，再设置用户环境变量：

```powershell
setx MEETING_COPILOT_STORAGE_DIR "E:\MeetingCopilotData"
```

重新启动后，新数据和导入的能力包会写入该目录。WebView2 运行缓存仍可能出现在系统盘的 `%LOCALAPPDATA%\com.meetingcopilot.desktop\EBWebView`，它不是模型目录。

## 工作台无法打开

先检查服务状态：

```powershell
cd code\web_mvp\backend
uv run python ..\..\..\tools\workbench_server.py status
```

如果前端来源校验失败，重新构建 `code/web_mvp/frontend_v2` 后再启动服务。若 `8765` 被占用，先停止旧进程，或在开发模式中为 Uvicorn 和 `VITE_DEV_API_TARGET` 使用同一个新端口。

## 页面有样式但接口报错

开发模式必须显式设置后端地址：

```powershell
$env:VITE_DEV_API_TARGET = "http://127.0.0.1:8765"
npm run dev
```

确认 `http://127.0.0.1:8765/health` 可访问，并检查浏览器控制台是否出现跨域、代理或网络错误。

## 麦克风不可用

1. 在 Windows 隐私设置中允许桌面应用访问麦克风。
2. 关闭正在独占设备的录音或会议软件。
3. 回到会议预检窗口重新选择输入设备。
4. 普通浏览器中确认站点的麦克风权限未被永久拒绝。

系统音频和双轨采集依赖 Tauri 桌面端；普通浏览器不提供相同能力。

## 没有实时转写

- 打开“离线能力”确认 ASR 运行时已就绪。
- 检查音频电平是否有输入。
- 确认能力包平台与当前系统匹配，且导入校验已完成。
- 查看诊断抽屉中的 ASR worker 和后台任务状态。

基础安装不包含完整离线模型时，需要先导入对应 `.mcpkg` 能力包。

## AI 建议或摘要不可用

1. 打开“设置”检查服务地址、模型和接口风格。
2. 重新输入 API Key 并执行连接检测。
3. 确认服务地址支持应用选择的 OpenAI-compatible 接口。
4. 检查账户额度、超时和网络代理。

AI 服务失败不会删除本地会议记录。恢复连接后可在复盘页面重试支持的分析任务。

## 导入录音失败

- 确认文件仍存在且当前用户有读取权限。
- 检查磁盘剩余空间。
- 使用常见音频格式，并避免损坏或只有容器头的文件。
- 不要从应用数据目录内部再次导入应用自己管理的音频。

## 生成诊断包

```powershell
code\web_mvp\backend\.venv\Scripts\python tools\generate_diagnostic_bundle.py
```

诊断文件写入已忽略的本地产物目录。对外发送前请检查其中是否包含不应分享的会议标题、文本或环境信息。
