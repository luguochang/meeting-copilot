# 隐私说明

Meeting Copilot 当前采用单用户、本地运行架构。本文说明默认数据流和用户启用远程 AI 后的变化，不替代组织自身的隐私合规要求。

## 默认保存在本地的数据

- 会议名称、时间和状态
- 实时与导入音频的转写结果
- 录音及处理后的受控音频
- 议题、建议、反馈、纪要和复盘文档
- 个人笔记
- 本地能力包状态、后台任务和诊断日志

这些数据保存在应用数据目录。开发模式默认使用 `artifacts/tmp/web_mvp_data/`，也可通过 `MEETING_COPILOT_DATA_DIR` 修改。

## 远程 AI 调用

远程 AI 默认未配置。用户在设置中保存 OpenAI-compatible 服务后，后端会把生成建议、摘要或文档所需的会议文本发送到该服务。具体留存、训练和地域规则由用户选择的服务提供方决定。

应用不会因为打开官网或启动本地服务而自动上传会议录音。当前远程分析路径以文本为主，不应把 API Key 写入官网、前端代码或 Git。

## 密钥

桌面端通过系统安全存储保存 provider 密钥，并使用脱敏状态与前端交互。源码运行时也可以通过环境变量提供密钥；`.env` 和本地配置文件已被 Git 忽略。

## 删除

删除会议会清理该会议在受控数据目录中的数据库事实、录音和派生任务。已经发送给第三方 AI 服务的内容不受本地删除控制；如需删除，应按对应服务方的政策处理。

## 诊断与日志

诊断包和日志用于定位本地运行问题。实现会过滤已知密钥、URL 凭据、敏感查询参数和本机绝对路径，但分享前仍应人工检查。`artifacts/` 下的诊断产物不会进入 Git。

## 官网

`website/` 是静态站点，不连接产品 SQLite、不读取录音或转写，也不持有产品 AI 密钥。官网中所有 `VITE_*` 配置都属于公开信息。
