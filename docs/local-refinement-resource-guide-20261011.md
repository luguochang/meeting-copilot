# 本地语音精修资源与校对策略

更新：2026-10-11。适用于 Windows 源码网页版。安装与启停见 [网页部署](web-deployment.md)，步骤见 [操作手册](realtime-participation-user-manual-20261008.md)，修改与测试见 [实现记录](correction-mode-implementation-20261011.md)。

**当前没有认证的最低机器配置。完整 CPU 双模型流程建议以 32 GB 内存作为部署验证起点，仍需实际可用资源通过检查；32 GB 参考机器也发生过精修准备失败。会前页面通过不代表本地精修、整场识别准确率或完整产品通过验收。**

## 1. 三层能力与实际状态

| 层次 | 输入与作用 | 资源位置 | 确认方式 |
| --- | --- | --- | --- |
| 实时语音识别 | 声音转在线草稿，闭合后保存识别正文 | 本地流式 Paraformer、CPU、独立 Python 进程 | 在线 worker 实际 ready，正式段有有效闭合边界 |
| 本地语音精修 | 对已闭合 PCM 重新识别，使用离线 ASR、VAD、标点模型 | 本地 CPU、另一驻留进程 | 离线 worker 实际 ready，段落有 `refinement_status=refined` |
| 大模型文字校对（L2） | 根据正文、上下文和已确认术语修正文字，校验原意、事实与数字 | 已配置的远端模型，本机负责队列与修订 | 校对用途记录、实际 revision 或 `no_change` |

`local_realtime_online_final` 是保存的在线识别正文；精修失败、加载中或明确跳过时，该段没有完成本地语音精修。合格闭合来源可以独立进入 L2，任意 partial 草稿不能直接晋升。`no_change` 表示未提出有效修改，不保证识别文字准确。模型文件齐全也不等于实际进程 ready。

## 2. 内存实测与限制

参考环境为 Windows 11 x64、i5-12400F（6 核 / 12 线程）、标称 32 GB RAM，OS 可见约 31.843 GiB。参考 GPU 约 8 GB 显存，但当前精修为 `--device cpu`，未使用 GPU 推理。

GB = 1,000,000,000 B；GiB = 1,073,741,824 B。私有提交、工作集与系统可用内存是不同指标。

| 实测项 | 精确值 | 有效范围 |
| --- | --- | --- |
| 在线 ASR 子进程私有提交 | 4,527,284,224 B，4.216 GiB | 单个在线 worker 一次采样，不是长会议峰值 |
| 同一在线工作集 | 3,184,295,936 B，2.966 GiB | 当时驻留物理页，不是全部提交需求 |
| 离线峰值私有提交 | 5,483,675,648 B，5.484 GB / 5.107 GiB | 一条公开 3.71525 秒 PCM 的冷加载、推理与退出 |
| 同次离线最高工作集 | 4,332,924,928 B，4.035 GiB | 同一专项，133 次采样 |
| 同次系统最低可提交余量 | 2,242,076,672 B，2.088 GiB | 接近保留余量，不是推荐会前余量 |

实际模型子进程的占用不能用 launcher 外壳代替。多个在线 worker、双声源、文件识别与其他应用会增加需求。在线采样加离线单次峰值约 9.323 GiB，只是规划估算，尚无双模型、长录音、浏览器与资料导入共存的完整并发峰值测量；系统和其他应用还需空间。

公开短 PCM 阶段冷加载内部 33.015 秒、外层 33.337 秒；推理内部 483 ms、外层 498.937 ms，worker 正常退出。**该测试报告整体仍失败**：后续产品 WAV 因容量预算不足拒绝，MP3 只转换未识别。短样本不能算完整文件导入、双路实时或低配验收。

## 3. 提交余量与保护预算

Windows 提交上限由 RAM 和分页文件共同支持，可提交余量不同于物理可用。分页文件不消除换页延迟，其大小取决于实际峰值与系统要求，没有通用固定倍数。[Microsoft 官方说明](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/how-to-determine-the-appropriate-page-file-size-for-64-bit-versions-of-windows)。本轮未修改分页配置。

[资源保护源码](../code/web_mvp/backend/meeting_copilot_web_mvp/asr_resource_guard.py) 的 `cold_load_provisional_v1` 使用 6 GiB 提交、4 GiB 物理预算，各加 2 GiB 保留量。无输入时冷加载需：

- 可提交余量至少 **8 GiB（8,589,934,592 B）**。
- 物理可用至少 **6 GiB（6,442,450,944 B）**。

已有模型的 `warm_inference_provisional_v1` 保留系统 2 GiB 余量，并加输入预算；输入按 PCM 字节数的 8 倍估算，以返回的 `required_*_bytes` 为准。运行时约每 250 ms 检查，触发后停止自身离线 worker 并保留原因。这是暂定保守准入，不是装机最低 RAM，也不是独占预留；会前通过不保证加载期间资源不下降。本轮未降低阈值或模型精度。

### 必须保留的真实失败

32 GB 参考机器一次显式准备前提交约 8.62 GiB、物理约 7.11 GiB；约 35.622 秒后提交余量降为 2,063,749,120 B（1.922 GiB），触发 2 GiB 保留量保护。结果是 `asr_resource_guard_triggered`、离线未 ready、推理请求 0、进程退出且清理完成、`recovery_required=true`；在线识别仍 ready。之后切到仅大模型模式正常，被动查询没有重新加载。不能写成完整精修通过。

## 4. 两种会议校对模式

| 模式 | 本场处理 | 边界 |
| --- | --- | --- |
| `local_and_llm` | 本地在线 ASR，资源允许时准备/复用本地精修，L2 独立处理有效正文 | 资源不足明确受控回退，不能伪造本地 ready |
| `llm_only` | 本地在线 ASR 加 L2；本场不申请、等待、调用或释放离线精修租约 | 名称指校对层，不向文字模型发送音频 |

服务启动先准备在线识别，离线重模型延后到本地模式会议租约或用户明确准备。进入收音后锁定模式，并发会议各自选择；不改历史段的真实来源。

被动接口 `/providers/asr/correction-capability` 分开返回总 RAM、提交/物理余量、冷/热预算、本地状态与 L2 配置：`available` 表示可尝试准备，`worker_ready` 才是真正就绪；`recovery_required/last_error_code` 保留旧失败，GET 不清除或重试；`llm_correction.enabled/configured` 独立判断。有效模式为仅大模型也不能在未配置时声称已校对。

资源恢复后仍需明确准备，不按每段重复冷加载；探测、依赖、一般模型或传输失败不冒充确认的容量拒绝。

## 5. 触发频率与独立 L2

本地精修按语音闭合边界处理：默认静音约 900 ms 判段，连续讲话约 15 秒上限走长段闭合逻辑，暂停/结束处理残留。不是每个 partial 都启动模型。活动会议期间复用，无租约通常闲置 120 秒卸载。

底层 `prewarm` 为本地模式会前准备；`on_demand` 在活动会议有实际音频时安排一次后台准备，实时接收不等待整个冷加载；`online_only` 明确跳过本地精修。这与会议模式是两层配置，标准入口按部署文档使用。

未精修在线正文只有有声 PCM、有效因果闭合 ACK、有效文本同时成立才保存正式段；保留资源失败或加载原因。无 ACK、无音频、任意 partial、不可信来源不晋升，普通模型/传输错误不借资源回退放宽。

L2 由有效正式段进入持久化队列，支持合并批次、版本过滤、原意/数字校验和显式重试；不要求先完成离线精修，也不是每秒固定调用。Pi 是另一用途，全部 LLM 记录不能算校对次数，文字校对不能重听 ASR 漏掉的声音。

真实使用的匿名汇总证明 L2 已调用：106 段中 48 修改、40 未提出有效修改、18 失败保留原文，有 11 条文字校对用途记录。记录不等于全部请求成功或收费次数；另一份未请求校对的恢复正文仍保持未处理，不能借用这份汇总称其完成。

## 6. 部署建议与未完成验收

| 项目 | 建议 | 未认证部分 |
| --- | --- | --- |
| 双模型 RAM | 32 GB 为 CPU 完整流程验证起点，仍查实际余量 | 16 GB 双模型、64 GB 对照及重度多任务保证 |
| 仅 L2 层 | 省离线进程，仍有在线 ASR 约 4.216 GiB 私有提交 | 16 GB 更适合仅是工程推测，没有低配整场认证 |
| CPU / GPU | 64 位多核，6C/12T 为参考；当前 CPU 路径不要求独显 | 低规格 CPU、笔记本限制、GPU 显存/速度 |
| 磁盘 | SSD 优先，安装/缓存预留 15–20 GB，录音另计 | 非认证最低容量，下载/cache 副本另计 |

推理文件约 3.105 GB，选定环境约 1.450 GB，合计约 4.555 GB 逻辑大小，未按硬链接去重，不是独占分配或新机下载量。16 kHz 单声道 16 位 PCM 约 115.2 MB/小时/音轨，journal 与组装 WAV 同留约两份，双轨、导入及诊断另外计算。

按仓库锁文件安装：后端 Python `>=3.11,<3.14`（流程选 3.13），ASR 选 3.11；本轮 FunASR 1.3.10、Torch 2.12.1，Pi 需 Node 22.19+。升级、GPU wheel 或其他系统不能自动视为已验收。

仍未完成：全新 Windows 安装、低配整场、双模型并发峰值、长会议/双轨资源、精修失败后恢复质量、识别准确率、连续教练价值和用户最终验收。已有构造回归与会前页面检查不替代这些项目。
